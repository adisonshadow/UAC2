## 探索中发现的事实修正(相对方案文档)

1. **`app_secret`/`client_secret` 库内是明文**(`applicationController.js:849` 直接比对),导出原样、导入原样;真正「解密导出→目标重加密」的只有 3 处:`aibase.providers.api_key_encrypted`、`bizdata.outbound_webhooks.auth_secret_enc`、`automation.hooks.action_config.auth.secretEnc`。`database_connections.password_enc` 不导出(§3.1)。
2. **`withPgTransaction` 是废弃的回滚测试工具**(恒 rollback),行数据导入事务改用 `withPgClient` 内手动 `BEGIN/COMMIT/ROLLBACK`。
3. **前端不是 umi**,是 Vite+React19+antd6+axios 自封装;blob 下载与 JSON 错误信封处理参照 `FileStorage/Browser/index.tsx:36-62`;`message/modal` 必须来自 `@/utils/antdAppApis`;antd6 用 `destroyOnHidden`。
4. **内置 API 权限已迁移到 catalog + `uac.builtin_api_configs`**,permissions 种子 SQL 不再承载 API 权限(该文件 50-51 行注释明确)。故 §5.1「同步种子」落地为:catalog.js 三条 + 新增 `scripts/migrate-app-transfer-permissions.sql`(三条 code 的 access_restriction 限 SUPER_ADMIN 角色 `10000000-0000-0000-0000-000000000001`,仿 `migrate-operation-log-audit.sql:51-54`)。
5. **`buildScopeAncestorCodes` 不存在**,scope_docs 筛选自行实现:code 或其前缀路径命中本次导出实体 code 的祖先链。

## 导出文件格式(format:"eadaf-app-export", formatVersion:1)

`options{dataMode, includeUac, includeAi, secretsInPlaintext:true, exportedAt, sourceApp{}}` + 节:`application`(密钥字段原样)、`entities{items,fields,enums,relations,scopeDocs,connectionsHint[]}`(Hint 仅 id/name/dbType/targetSchema/isDefault,无密码)、`entityData[]`(data_only 时 items 仍导出但 rows 仅在 structure_and_data 带出;rows 保留原 PK)、`apiServices{items,operations,permissions}`、`collectionPipelines{items,applications(仅本应用)}`、`outboundWebhooks`、`metrics{items,cards}`、`hooks`、`skills{items,tools,scopes,skillTools,applications}`(默认仅 dedicated;includeAi 追加 global)、`ai{providers,models,capabilities,ioTags}`(仅 includeAi)、`uac`(includeUac:users/departments/userRoles/roles/permissions/rolePermissions/dataPermissionRules;否则仅被引用 roles+permissions)、`storageBuckets`(仅元数据)。

**筛选统一走 §3.5 表**:实体/枚举/指标用 `prefixHit(code, A.bizdata_scope_codes)`;指标卡片 domain_code;API 用 `api_data_scope` 优先(matchesApiDataScope 复用)空则回退 prefixHit;Webhook 用 `matchesOutboundWebhookScope(code, A.outbound_webhook_scope)`,全空回退 trigger_api_service_code ∈ 本次 API 集合;管道 prefixHit 且 pipeline_applications 只留本应用;hooks 筛 event_filter JSON 串含本次 entity/api code;关系两端都在实体集合内;运行时表(runs/values)全排除。

## 导入实现要点(按 §3 修订)

- **依赖链顺序**:uac 最小结构→application→entities(+enums/relations/scopeDocs)→物化→entityData→apiServices→collectionPipelines→outboundWebhooks→metrics→hooks→skills→storageBuckets;链上失败即终止(返回已完成节计数);includeUac 用户数据、includeAi providers 失败单独标红不阻断。
- **连接只匹配不创建**:is_default&&db_type → (db_type,target_schema) → name(仅提示);失败则该实体行数据 failed。
- **元数据 upsert 键**:application/实体/枚举/管道/Webhook/指标/卡片/桶=code;api_services 第二键 route_path、管道第二键 route_path、tools 第二键 function_name——overwrite 时第二键撞到**另一条**目标记录→该条 failed 不静默改;abort 列入清单。用户=username,角色/权限=code,departments=name+父链(导入后重建 department_closure)。relations 键 `(type,name,fromCode,toCode)`(缺端 skip+警告);hooks 键 `(name,event_type)`(多条命中→failed)。
- **行数据**:仅 PG/MySQL;overwrite=DELETE FROM 后按实际列集批量 INSERT(同连接事务),保留源 PK;先 information_schema 校验列,缺列/类型不兼容→该表 failed 带 DDL 差异;data_only 模式:不落结构,目标无同 code 实体或 version 不符→跳过写数并报告。
- **物化**:结构导入后按匹配连接分组调 `executeMaterialization({connectionId, expectedVersions:{新实体id:文件version}, createTargetIfMissing:true})`。
- **密文往返**:3 处加密字段导出解密为明文段、导入用目标 `ENCRYPTION_KEY` 重加密;文件头校验 `secretsInPlaintext`。
- **api_service_permissions**:`grant_type=application` 仅留指向本应用行并 remap;role 行指向已导出角色则 remap 否则 skip+报告;department 行仅 includeUac 且命中时 remap。
