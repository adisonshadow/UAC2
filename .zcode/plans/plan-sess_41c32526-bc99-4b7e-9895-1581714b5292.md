# 升级 ScopeDomainTree 支持树状勾选 + 版本信息,并让物化执行页改用它

## 问题根因
物化执行页左侧「第一层第二层合在一起」是因为数据层(`useMaterializationData.ts:50-57`)先用 `buildScopeTree` 正确建了多级树,又**立刻 `flattenScopeTree` 扁平化**成一层 scope 分组,`EntitySelector` 只渲染两层(scope → 实体),丢失了中间层级。

## 目标
升级 `ScopeDomainTree`(metrics 域树组件)让它支持 **可勾选(父子联动)+ 叶子节点自定义渲染(版本 Tag)**,然后让物化执行页改用它渲染真正的多级树,删除旧的 `EntitySelector`。

## 改动清单

### 1. 升级 `frontend/src/components/ScopeDomainTree/index.tsx`(向后兼容,不破坏 3 处现有调用)

**扩展数据结构 `ScopeDomainTreeNode`**——新增可选字段承载叶子附加数据:
```ts
export interface ScopeDomainTreeNode {
  code: string;
  name: string;
  itemCount?: number;
  children?: ScopeDomainTreeNode[];
  // 新增:叶子节点的附加数据(物化版本/状态),域节点不传
  leafData?: {
    value: string;              // 实体 id,作为 checkable 的 key
    currentVersion?: number;
    materializedVersion?: number | null;
    staleStatus?: 'latest' | 'stale' | 'not_materialized';
  };
}
```

**新增 props**(全部可选,默认行为不变):
```ts
- checkable?: boolean              // 开启勾选模式
- checkedKeys?: string[]           // 受控勾选 keys(实体 value)
- onCheck?: (keys: string[]) => void
- renderLeafTitle?: (node: ScopeDomainTreeNode) => React.ReactNode  // 自定义叶子标题(渲染版本 Tag)
- showAllNode 在 checkable 时变成「全选」:勾上=全选所有叶子,半选态自动计算
```

**实现要点**:
- `checkable` 模式下用 antd Tree 的 `checkable` + `checkedKeys` + `onCheck`,**父子联动由 antd 内置**(`checkStrictly=false` 默认)。key 用 `leafData.value`(实体 id),域节点 key 仍用 code。
- 叶子节点标题:`renderLeafTitle` 优先,否则回退现有 `renderNodeTitle`。
- 「全部」节点在 checkable 模式:`key=ALL_NODE_KEY`,checked 状态 = 所有叶子是否全选;onCheck 时若包含 ALL key 则展开为所有叶子 value。
- 保持 `selectedKeys`/`onSelect` 完全独立(metrics 等页继续用单击选中过滤,不受 checkable 影响)。
- 3 处现有调用(Metrics / Materialization-Database / ApiServiceDomainTree)不传新 props,行为零变化。

### 2. 改造数据层 `frontend/src/pages/BusinessData/Materialization/hooks/useMaterializationData.ts`
- 删除 `EntitySelectorItem` 类型和 `groupedOptions`(扁平化逻辑)。
- 新增导出 `scopeTree: ScopeDomainTreeNode[]`:把 `buildScopeTree(erEntities)` 的 `ScopeTreeItem[]` 转成 `ScopeDomainTreeNode[]`,并把物化状态(`statusByEntityId`)挂到叶子节点的 `leafData`。**不再扁平化**——保留完整多级树。
- 返回值:`{ entities, erEntities, scopeTree, statusItems, loading, ... }`(移除 `groupedOptions`)。

### 3. 改造页面 `frontend/src/pages/BusinessData/Materialization/Execute/index.tsx`
- 把 `<EntitySelector>` 替换为 `<ScopeDomainTree>`,传入:
  ```tsx
  <ScopeDomainTree
    treeData={scopeTree}
    checkable
    checkedKeys={selectedIds}
    onCheck={setSelectedIds}
    showAllNode
    allNodeLabel="全选"
    renderLeafTitle={(node) => <LeafTitleWithVersion ... />}}
    loading={loading}
    emptyDescription="暂无实体"
  />
  ```
- 版本 Tag 渲染逻辑(颜色/tooltip/格式化)从旧 `EntitySelector` 搬到一个共享小组件(放 `ScopeDomainTree` 同目录或 Materialization 的 components),供 `renderLeafTitle` 调用。

### 4. 删除旧组件 `frontend/src/pages/BusinessData/Materialization/components/EntitySelector.tsx`
- 删除整个文件(已无引用)。
- `useMaterializationExecute.ts` 是无引用的死代码,**本次不动**(超出范围,避免连带风险)。

## 不做的事

## 风险
- **向后兼容是核心风险点**:3 处现有调用依赖现有 props。新 props 全部可选 + 默认值与现状一致,保证不传时行为不变。会用 `tsc` + 手动确认 3 处调用点 props 不变来兜底。
- 父子联动 key 设计:域节点 key=code,叶子 key=实体 value,两类 key 不会冲突(实体 id 是 UUID 风格,code 是冒号路径)。
