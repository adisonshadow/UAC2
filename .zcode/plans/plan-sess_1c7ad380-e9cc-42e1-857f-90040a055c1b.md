## 方案要点（文档将完整展开）

### 前端
- `pages/System/Settings/index.tsx` 的 Tabs 新增 `{ key: 'app-transfer', label: '导出/导入应用' }`，内容组件放新文件 `pages/System/Settings/AppTransferTab.tsx`。
- Tab 首行两个按钮：导出应用数据（primary）、导入应用数据。
- 导出 Modal：选择应用（Select，取 /api/v1/applications）+ 导出内容 Radio（数据和结构 / 仅数据）+ 两个 Checkbox（包含用户/组织/权限数据、包含AI数据）+ 导出按钮；点击后 POST 导出接口，前端按 Blob 下载 .json 文件（复用 FileStorage Browser 的 triggerBlobDownload 模式）。
- 导入 Modal：Upload.Dragger 选 .json → 前端解析展示摘要（来源应用/时间/各节条数）→ 选冲突策略 → 二次确认 → POST 导入 → 分节展示新增/更新/跳过/失败结果（参考备份恢复 Modal 的长超时模式）。
- API 封装加在 `services/UAC/api/system.ts`，类型加 typings.d.ts。

### 后端（全新模块）
- 新路由 `routes/appTransferRoutes.js`（prefix `/api/v1/system/app-transfer`）：POST /export（JSON 返回）、POST /preview（上传文件，校验+冲突清单）、POST /import（上传文件+策略，分节执行）。挂载进 routes/index.js，沿用 authWithBuiltinApiGuard + operationAudit 模式（同 systemRoutes）。
- 新服务 `services/appTransfer/appExportService.js`、`appImportService.js`。

### 导出内容与筛选规则
1. **应用本体**（始终）：uac.applications 该行完整配置（bizdata_scope_codes、api_data_scope、builtin_api_scope、outbound_webhook_scope、top_level_skill_markdown、sso 等）。内置应用 EADAF 建议禁止导出。
2. **数据实体设计**：实体 code 命中 bizdata_scope_codes 任一前缀的 entities + entity_fields + 相关 scope_docs。"数据和结构"= 结构+物化行数据；"仅数据"= 只导行数据（记录导出时实体 version 供导入校验）。json_schema 实体无行数据。
3. **API 服务**：优先按应用 api_data_scope（serviceCodes 精确 + domainCodes 前缀），为空回退 bizdata_scope_codes 前缀；附带 api_service_operations、api_service_permissions，排除运行记录。
4. **采集管道**：管道 code 顶层段（首段）∈ 应用 Scope 顶层段集合；附带来源应用白名单行。
5. **提交外部API**：绑定的业务 API（trigger_api_service_code）顶层段与应用顶层段一致；auth_secret 等密文原样导出并警示。
6. **SKILL/Tools**：is_global 全部 + is_dedicated 且经 skill_applications 绑定该应用的；连带 skill_tools、tools、引用的 aibase.scopes（注意这是与数据域不同的另一套 Scope 表）。
7. **AI 数据**（勾选）：providers、models、capabilities、io_tags 全量。
8. **用户/组织/权限**（勾选）：users、departments(+closure)、roles、permissions、各授权关联表、data_permission_rules、builtin_api_configs 全量；未勾选时仍导出被导出内容引用的权限/角色定义（最小"结构"），对应"无论如何结构一定导出"。

### 导入设计
- 按唯一键 upsert（applications.code / entities.code / *.code / skills.slug / users.username 等），冲突策略：覆盖更新（默认）/ 跳过 / 终止。
- 所有 UUID 重新生成，内部维护 oldId→newId 映射重映射全部外键。
- 导入顺序：应用 → UAC → 实体结构 → 物化（executeMaterialization）→ 行数据 → API 服务 → 管道 → Webhook → Skill/Tool → AI；分节报告结果，失败节不影响其他节。
- 行数据仅支持 PG/MySQL 物化连接，其余提示跳过。
- 敏感字段（api_key_encrypted、auth_secret_enc、password_hash、api_connect_config）原样导出/导入，UI 与文档警示文件含敏感信息。
