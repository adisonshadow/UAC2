## M0 生产写路径拆分（阻塞一切事件语义）

1. **`backend/src/services/apiService/sqlDialect.js`**
   - `updateThenSelect`（L272-319）：返回值增加 `before`——MySQL 分支已有 `selBefore` 直接带上；PG 分支更新前补一次 SELECT
   - `selectThenDelete`（L324-359）：两方言已返回被删行 `item`，补 `before: item` 别名统一信封
2. **`backend/src/services/apiService/apiServiceExecutionService.js`**
   - `executeUpdateOne` / `executeDeleteOne` 透传 `before`（`{item, matched, before}`）
   - 抽公共核心，新增导出 `executePublished(serviceId, opts)`：与 `testService` 相同校验链，但写操作 **rollback:false（真实 COMMIT）**；返回值附带执行元信息（`entityCode`、`operation`、`write: {before, after, changedFields}`——仅网关实体写，自定义 SQL / TS Handler 不含）
   - `testService` 签名与默认回滚行为不变（测试台 / AI 测试不受影响）
3. **`backend/src/services/apiService/apiServiceInvokeService.js`**
   - `invokePublished` 改调 `executePublished`；成功后 fire-and-forget：emit `apiservice.invoked` + 网关实体写 emit `bizdata.record.created|updated|deleted`（含 before/after/changed_fields）；失败 catch 后 emit `status:'failed'` 再 rethrow
   - 旧 webhook 触发保留但改为不 await（修复蓝本指出的请求路径 await 缺陷，M4 前旧功能继续可用）
4. **`backend/src/services/apiService/apiServiceWebSocket.js`**：生产 WS 写同样改走 `executePublished`（修复同缺陷），不发事件（蓝本边界）
5. **验证**：docker PG + init-db + 起服务；curl 调已发布写 API → DB 真实落库、响应正常；Admin 测试台写 → 仍回滚

## M1 后端钩子核心

**数据库**：`scripts/migrate-hook-center.sql`（蓝本 §3.12 DDL：automation schema、软删状态、快照列、无 CASCADE、去重唯一索引）+ `initdb.sh` 挂载；`models/automation_hook.js` / `automation_hook_run.js` + `models/index.js` 注册关联导出

**新模块 `src/services/automation/`**：
- `eventCatalog.js` — 8 事件类型（type/label/payload Schema/示例/可用过滤项），单一事实源
- `eventContext.js` — AsyncLocalStorage 携带 depth
- `hookRegistryCache.js` — enabled 钩子内存缓存 + 过滤预编译（Set/表达式预 parse）+ CRUD 失效重建
- `eventDispatcher.js` — `emit()` 统一信封（id/type/occurredAt/depth/payload）→ 匹配 → 进程内队列（全局并发 20、队列深度 500 超限记 suppressed）；永不向请求路径抛错
- `hookExecutor.js` — 重试退避（默认 2 次 1s/4s/16s）、超时、单钩子并发 3、Run 落库（run_group/attempt/脱敏快照/hook_version）、连续失败 10 → `auto_disabled`、test/replay 入口（重放新 event_id）
- `actions/httpRequestAction.js` — `{{payload.*}}` 插值 + 鉴权（encryption）+ transform（复用 outboundScriptRuntime）+ 响应判定（outboundResponseRules）+ 默认 30s 超时
- **SSRF**：新建 `outboundWebhook/outboundSsrfGuard.js`（DNS 解析后拦私网/回环/链路本地/metadata；fetch 改手动跟随重定向 ≤3 跳逐跳校验），挂入 `outboundHttpClient.requestJson`（旧 webhook 同时受益）
- `actions/internalApiAction.js` — 插值后调 `executePublished`（系统身份），ALS depth+1
- `actions/scriptAction.js` + `hookScriptRuntime.js` — 泛化 vm 沙箱（`handler(event, ctx)`，ctx.log 落 Run、白名单全局、5s 默认 30s 上限）+ handlerSdk 受控 DB（默认系统库连接，可指定 connectionId）+ 源码≤20000/输出≤50000
- `hookTypeCheck.js` + `hookSdk.d.ts` — 照 handlerTypeCheck 虚拟文件三件套（含 HookEvent 信封类型）
- `hookScheduler.js` — cron 钩子动态注册（node-cron + Redis 锁，metricScheduler 模式）+ Run 保留清理（30 天/每钩子 1000 条）+ `refreshHookScheduler()`
- `hookService.js` — CRUD/软删/启停（启用清零失败计数）/测试/重放/listRuns（成功率只计 event|schedule）/formatHook 掩码；写后失效缓存 + 刷新调度器

**接线**：`authController.js` 登录（L203 后）/登出（L457 后）emit；`app.js` listen 回调启动 `startHookScheduler`；`controllers/automationHookController.js` + `routes/automationHookRoutes.js`（prefix `/api/v1/automation`，全 `authWithBuiltinApiGuard`，Swagger JSDoc）+ `routes/index.js` 挂载；**`builtinApi/catalog.js` 真登记** 11 个端点（新 domain `automation`）

**验证**：curl 建 cron 钩子（脚本写测试表）→ 到点 Run success；登录 → Run 产生；Data API 写 → record 事件 Run 含 before/after；递归链 depth≥3 → suppressed；失败钩子 → 重试 → auto_disabled
